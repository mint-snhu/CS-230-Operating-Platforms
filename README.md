# CS-230-Operating-Platforms

Briefly summarize The Gaming Room client and their software requirements. Who was the client? What type of software did they want you to design?

The Gaming Room client wanted to expand its game, Draw It or Lose It, into a web-based application that could run on multiple platforms. The client wanted a software that needed to support multiple teams and players while ensuring unique game names and identifiers.

What did you do particularly well in developing this documentation?

I did well organizing the software design document and identifying the client’s requirements. The software design document helped me understand the software’s structure before coding, which made it easier to plan classes.

What about the process of working through a design document did you find helpful when developing the code?

Instructor feedback during the process of working though the design document made it helpful for me in developing the code as professor feedback allowed me a better understanding of how to improve my documentation. 

If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

My evaluation and recommendation parts of the document would be chosen to revise. I believe I would have elaborated more on my choices and explained furthermore how each component correlated in order to improve the overall documentation. 

How did you interpret the user’s needs and implement them into your software design? Why is it so important to consider the user’s needs when designing?

I focused on the client’s needs by breaking down each component and requirement set by the clients to ensure that each item was implemented in the software design. Considering user needs is important because software designs should meet expectations and solve the business problem at hand.

How did you approach designing software? What techniques or strategies would you use in the future to analyze and design a similar software application?

My approach involved analyzing requirements by the client and planning a UML diagram before coding. In the future, I will continue to use UML diagrams and requirements analysis in order to design a similar software application.
